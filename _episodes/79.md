## Releases and news

Following are highlights and selections from the releases since episode 78.
Check the full release notes for details.

### [Trino 480]({{site.baseurl}}/docs/current/release/release-480.html)

* Add the `number` data type.
* Add the DataSketches functions.
* Allow query parameters in the `FOR VERSION AS OF` and `FOR TIMESTAMP AS OF`
  clauses.
* Add cluster status information to the header of the preview Web UI.
* Improve performance of remote data exchanges and aggregations.

### [Trino 481]({{site.baseurl}}/docs/current/release/release-481.html)

* Add support for the `NEAREST` clause for approximate matches in joins.
* Add support for the `variant` type to the JDBC driver and the CLI.
* Add support for persisting external authentication tokens across JDBC client
  processes.
* Replace the Esri geometry library with JTS.
* Remove legacy object storage support for Azure Storage.

### [Trino 482]({{site.baseurl}}/docs/current/release/release-482.html)

* Add support for named arguments in function calls.
* Add support for the `AT LOCAL` operator, and the `MATCH` and `UNIQUE`
  predicates.
* Add the `ends_with` and `OVERLAY` string functions.
* Add buttons to cancel or preempt a running query to the preview Web UI.
* Remove support for the Alluxio file system.

### [Trino 483]({{site.baseurl}}/docs/current/release/release-483.html)

* Add support for the [PIVOT]({{site.baseurl}}/docs/current/sql/pivot.html)
  clause.
* Add support for the `OVERLAPS` predicate and the `title_case` function.
* Add numerous geospatial functions, including `ST_Transform`.
* Make the redesigned Web UI the default.
* Add support for themed, colorized output to the CLI.

As always, numerous performance improvements, bug fixes, and other features were
added as well.

## Introducing Jan and João

Jan tells us how he started with Trino at Starburst, and how his pull requests
for the Go client led to him becoming its maintainer. He also maintains the
[Helm charts](https://github.com/trinodb/charts) and the
[Grafana plugin](https://github.com/trinodb/grafana-trino).

João is a senior software engineer at ABC Fitness in Portugal, where his team
uses Trino and Go for CRM workflows. A pull request to fix query cancellation
was his start, followed by many more contributions to the Go client.

## Going for 1.0.0

We talk about the history of the
[trino-go-client](https://github.com/trinodb/trino-go-client), which was forked
from the original Presto driver, and the recent push for feature parity with the
JDBC driver. A [tracking
issue](https://github.com/trinodb/trino-go-client/issues/184) from [Sylwester
Lachiewicz](https://github.com/slachiewicz) listed the gaps, and he addressed
most of them. João added support for the
[`number` type](https://github.com/trinodb/trino-go-client/pull/177) and
[transactions](https://github.com/trinodb/trino-go-client/pull/217) through the
standard `database/sql` interface.

Jan explains how the spooling protocol works and João tells us how they
implemented it with a pipeline of goroutines for
[fetching](https://github.com/trinodb/trino-go-client/pull/138), downloading
and decoding segments [in
parallel](https://github.com/trinodb/trino-go-client/pull/141), while keeping
the results in order and memory usage bounded.

We also discuss mapping the Trino data types to Go types, binding Go slices and
maps as query parameters, and the breaking changes in 1.0.0. The new generic
scanners [replace](https://github.com/trinodb/trino-go-client/pull/250) the
hand-written slice and map types, and 0.338.0 is the recommended stepping stone
for upgrades. Since then,
[1.1.0](https://github.com/trinodb/trino-go-client/releases/tag/v1.1.0) added
the remaining data types, including intervals, and
[1.2.0](https://github.com/trinodb/trino-go-client/releases/tag/v1.2.0) uses
the new JSON v2 package and requires Go 1.27.

We chat about how AI tooling helps maintainers and contributors with gap
analysis, reviews, and the tasks nobody wants to do. Jan then demos nested data
types with generics, the `variant` type, time zone fixes, transactions, and the
lower memory usage with JSON v2. He also covers OAuth 2.0 and Kerberos
credential cache support.
